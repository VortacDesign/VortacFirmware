Troubleshooting

Known failure modes, sorted by symptom. Each entry expands to cause and fix.

Installation & deployment

vortac_configs/ shows up empty in the config folder

Cause: the systemd automount hasn't been triggered yet, or the web interface is showing a cached file tree.

Fix: run sudo ./install.sh manually once more, then clear your browser cache and reload the web interface — Mainsail/Fluidd caches the file tree.

Changes to a .py file don't take effect on the printer

Checklist:

  • Did the Pi actually pull? (git -C ~/vortac log -1)
  • The .path watcher re-runs install.sh on pull, but Klipper is not restarted automatically: sudo systemctl restart klipper.
  • Is the file symlinked? ls -la ~/klipper/klippy/extras/ | grep vortac. The installer skips files that already exist as real (non-symlink) files — remove the stale copy and re-run install.sh.
  • New .py files only get linked when install.sh runs — after adding a module, make sure it ran (a pull triggers it, or run it manually).
Klipper error: Section 'vortac_…' is not a valid config section

Cause: the extra isn't symlinked into Klipper's klippy/extras/ (installer never ran, or Klipper lives in a non-default path).

Fix: run sudo ./install.sh (set KLIPPER_DIR if Klipper is not at ~/klipper), then restart Klipper.

Configuration

One "franken-tool": a board behaves as if it had the other tool's config

Symptom examples: one board shut down by the other tool's sensor config; LEDs or fans reacting on the wrong tool; only one tool showing up although two are configured.

Cause: a copied tool file where an occurrence of the old tool name was missed. Klipper silently merges duplicate config sections (last value wins), so this never errors on its own.

Fix: grep the new tool file for the old name and rename every occurrence. With the current conventions the name only appears in two headers — [mcu <name>] and [include_with <name> …] — everything else (sense pins, [vortac_tool <name>], extruder_name) is injected from the PCB template. vortac_manager refuses to start on the conflicts it can detect (duplicate index/MCU/UUID/sense pins) — fix what it names.

MCU shutdown: Thermocouple reader fault

Cause: MAX31865 RTD configuration doesn't match the board's reference resistor.

Fix: pairing rule of thumb — PT100 → rtd_reference_r: 430, PT1000 → rtd_reference_r: 4300. Check the actual reference resistor on your board and set the values via overrides: on the tool's [include_with] section (see Configuration → overrides).

Section collision between tools (e.g. input_shaper defined twice)

Cause: bare Klipper singletons without a name part can't be namespaced by include_with. The known ones (resonance_tester, input_shaper, shaketune) are skipped automatically for tool_index ≥ 1; anything else passes through unchanged.

Fix: add the section to skip_sections: on the colliding tool's [include_with].

Tool file commented out, but [vortac_tool <name>] is still in printer.cfg's autosave block

This is by design, not an error. Dock calibration (params_<dock>_x/y/z) is persisted via SAVE_CONFIG into [vortac_tool <name>] in the autosave block. When the tool's include is commented out, that section remains and loads as a harmless ghost: no sense pins configured → available defaults to False, the manager skips it, and the calibration data survives until the tool returns. Don't delete it unless the tool is gone for good.

Set available: True explicitly only for a genuinely sense-pin-less tool (degraded blind-unhook mode) — never to "fix" a ghost.

Startup error: tool_index values … are not contiguous 0..N-1

Cause: with order-based numbering this holds by construction, so the error usually means an explicit tool_index: was mixed with auto-numbered includes (the per-printer counter ignores explicit values), or a vortac_tool section was skipped (e.g. via skip_sections:) while another include already counted past it.

Fix: let the include order in tools.cfg do the numbering — remove explicit tool_index: options from tool includes (or use them on all tools consistently), and don't skip the template's vortac_tool placeholder on some tools but not others.

Grabber & calibration

VORTAC_MOVE doesn't converge, or needs many passes
  • Stale or missing LUT — re-run VORTAC_CALIBRATE + SAVE_CONFIG. Verify with VORTAC_MESURE: lutPairs/finalPairs must be a straight line with slope 1.
  • Mechanical backlash — VORTAC_CALIBRATE DIR=both reports it (Backlash … mean/max). If it is large, use direction-constrained modes (MODE=cw|ccw, engage_mode/disengage_mode) and calibrate with DIR= that direction.
  • Lost steps (binding, too-high speed, too-low stepper current) — lost steps show up as a constant surprise in the next absolute reading. Check that the grabber rotates freely and reduce SPEED.
  • Noisy sensor reads — increase READS and READ_SETTLE.
True angle wrong / jumps at one spot on the circle

Cause: LUT seam handling problems usually come from a calibration run where the sensor seam fell exactly on a bin, or from an aborted calibration.

Fix: re-run VORTAC_CALIBRATE (the default PHASE pre-roll of half a bin places the seam between bins). Verify the full circle with VORTAC_MESURE SAMPLES=180 and plot via dev_scripts/plotData.py — exactly one clean wrap at the 360° seam is expected.

Calibration OK but zero position is off after restart

Cause: SAVE_CONFIG was skipped — lookup_table and zero_pos_offset are only staged via configfile.set until then.

Fix: re-run VORTAC_SET_ZERO (approach the reference in the operating direction if you use cw/ccw modes), then SAVE_CONFIG.

Dock detection

VORTAC_DETECT aborts before strobing

Cause: a tool already reads dock LOW while all dock Tool_id channels are off — the mapping would be ambiguous. Usually a wiring/polarity issue on dock_sense_pin, ambient light triggering the opto, or a dock LED channel that is not actually controlled by the configured argb_led/argb_channel.

Debug: VORTAC_SENSE_STATUS for the raw pin states, VORTAC_DOCK_STROBE DOCK=dockN VALUE=0/1 to toggle a single channel manually, VORTAC_SENSE_MONITOR DURATION=10 while toggling to watch transitions. Check the pin inversion (!miniGrey:PB15) against your opto logic.

A tool never flips on its dock's strobe
  • Dock LED chain index vs. dockN mismatch — docks map to LED chain indices; verify with VORTAC_DOCK_STROBE that the right physical LED lights up.
  • Wrong argb_channel (Tool_id strobe is the green channel by default).
  • dock_strobe_time too short for the opto to settle — raise it in [vortac_manager].
  • Run VORTAC_DETECT DEBUG=1 for per-strobe detail.
Tool change fails: no dock known … — run VORTAC_DETECT

Cause: docks are established at runtime by VORTAC_DETECT (home_dock is only an optional manual fallback), and no detection has run yet — the manager has no dock to fetch the tool from or park it at.

Fix: run VORTAC_DETECT before the first tool change — put it in your PRINT_START. Alternatively, pin a manual fallback on the tool via include_with overrides (vortac_tool TN.home_dock: dockX).

Warning after VORTAC_DETECT: grabbed tool has no free dock with calibrated positions

Cause: a grabbed tool is assigned the first free dock that has calibrated positions for it (a previous choice — fetch origin or manual home_dock — is kept if still free and calibrated). If every calibrated dock is occupied, or no dock was ever calibrated for this tool, detection warns: VORTAC_UNLOAD / tool changes will fail until a dock is calibrated for it or a dock is freed.

Fix: calibrate a dock position for the tool (Calibration → Dock positions, or the manual VORTAC_DOCK_SAVE_POS fallback), or free an already-calibrated dock, then re-run VORTAC_DETECT.

Probing & gantry

QUAD_GANTRY_LEVEL / PROBE / BED_MESH_CALIBRATE refuses to run

Cause: this is the manager's probe guard, not an error. A tool is held (logically, or a grab_sense pin reads grabbed). Probing with a tool would crash the nozzle into the bed — the probe touch point sits above the nozzle tip.

Fix: VORTAC_UNLOAD, probe, then pick the tool back up. If no tool is physically held but the guard still triggers, check VORTAC_SENSE_STATUS — a stuck/misconfigured grab_sense_pin reads as grabbed — and clear a stale logical tool with VORTAC_SET_CURRENT_TOOL CLEAR=1.

First layer / dock approach wrong after a restart or Z-home

Cause: the FLAT/TILT state of [vortac_qgl_state] is RAM only. A power cycle, a Klipper restart or a fresh Z-home resets it to flat and clears the stored QGL deltas.

Fix: re-run QUAD_GANTRY_LEVEL (with no tool held) before printing. Check with VORTAC_QGL_STATUS. If Z was re-homed while a tool was held: VORTAC_UNLOAD → QUAD_GANTRY_LEVEL → reload the tool.

VORTAC_DOCK_CAL_SAVE / VORTAC_DOCK_SAVE_POS refuses
  • Gantry is tilted — dock geometry is only valid frame-flat: VORTAC_GANTRY_FLAT first.
  • No dock/tool selected — run VORTAC_SELECT_DOCK DOCK=dockN (which needs the tool to be detected in that dock) before VORTAC_DOCK_CAL_SAVE.

Checkboxes don't stay checked

Checklist state is stored in your browser's localStorage, keyed per page. It is lost if you clear site data, use a private window, or open the docs from a different origin/path. Some browsers restrict localStorage for file:// pages — serving the folder (e.g. python3 -m http.server in DOCS/) always works.
