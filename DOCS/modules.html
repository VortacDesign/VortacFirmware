Module Reference

Internals of the Klipper extras in klippy/extras/. For the command tables, see the G-code Reference.

The Klipper plugin contract

Klipper imports an extra when it sees a config section matching the file name. The factory functions are load_config(config) for singleton sections ([vortac_grabber]) and load_config_prefix(config) for prefix sections ([vortac_tool T0], [include_with foo bar]). Extras look up shared objects via printer.lookup_object(…), register commands via gcode.register_command(…), and persist tuned values via configfile.set(…) + user-run SAVE_CONFIG.

vortac_grabber — [vortac_grabber]

Hardware-only module: AS5047D angle sensor (SPI), closed-loop control of the [manual_stepper grabber], LUT-based raw→true angle interpolation.

  • Python API (called by the manager): engage(angle=None, gcmd=None), disengage(gcmd=None), read_angle(gcmd=None).
  • Calibration (VORTAC_CALIBRATE): synchronous direct-read (multi-turn, last-turn-wins, circular mean per bin). DIR=both (default) sweeps cw then ccw, stores the per-bin circular midpoint and reports the cw/ccw spread as a backlash measurement. Details in Calibration.
  • Closed-loop moves (VORTAC_MOVE, engage/disengage): each pass commands the full remaining error in one force_move.manual_move, re-measures, repeats — typically 1–2 moves; lost steps show up in the next absolute reading. MODE=cw|ccw constrained moves stop max(BACKOFF, GUARD_FRAC·dist) short per pass so overshoot never forces an extra revolution. cw means increasing true angle.
  • Persistence: lookup_table and zero_pos_offset are written via configfile.set → user runs SAVE_CONFIG.

Deep dive: angle math on a circle

All angle math wraps to [0, 360) and must handle seam crossings. The wrap360 / wrap180 / circ_mean helpers in vortac_grabber.py are the reference implementations — _measured_to_true does wrap-aware circular interpolation across the LUT, including entries that straddle the 0°/360° seam. read_raw builds 16-bit AS5047D SPI commands (with parity bit) and returns the angle in degrees at 14-bit precision.

Deep dive: the standard stepper-nudge pattern

The grabber stepper is never driven through the kinematics path. The standard pattern is force_move.manual_move(stepper, distance, speed) followed by toolhead.wait_moves() and a small dwell to let the sensor settle before reading. Keep this pattern for any new grabber motion code.

vortac_tool — [vortac_tool <name>]

Per-tool logical definition. Normally injected by include_with from the PCB template's [vortac_tool TN] placeholder (identity auto-filled); a statically written [vortac_tool T0] still works. The tool hardware must already be present in normal Klipper config ([mcu <name>] plus [include_with <name> …]) before this extra loads — Klipper registers MCU pin chips before extras run.

  • Identity: injected sections get tool_index, mcu_name, display_name (<namespace><index> — the dashboard prefix of the injected hardware sections, also exposed via get_status; address hardware index-proof in macros via {tool.display_name}_logo_rgb) and extruder_name from include_with; static [vortac_tool T1] sections derive them from the trailing number (T1 → index 1, tool1, extruder1, home_dock=dock1). home_dock is not derived from the (order-based, unstable) tool_index and is optional — docks are established at runtime by VORTAC_DETECT; a manual fallback can be pinned via include_with overrides (vortac_tool TN.home_dock: dockX).
  • Availability & ghosts: available: defaults to True only when both sense pins are configured. A leftover autosave-only section (a commented-out tool whose SAVE_CONFIG'd params_* dock positions remain in printer.cfg) therefore loads harmlessly as a "ghost": tool_index=None, available=False, calibration preserved until the tool file returns. A genuinely sense-pin-less tool (degraded blind-unhook mode) must set available: True explicitly.
  • Per-dock storage: params_<dock>_<x|y|z> (persisted via configfile.set + SAVE_CONFIG; keyed by tool NAME, so calibration survives renumbering). Manager-facing API: get_dock_pos(dock, axis), has_dock_pos(dock), save_dock_pos(dock, x, y, z).
  • Templates: tool_activate_gcode / tool_deactivate_gcode — run by the manager around the dock motion. Jinja context: tool (this VortacTool), dock=None, params.

vortac_manager — [vortac_manager]

The coordinator. At klippy:connect it discovers all [vortac_tool *] sections (only those with available=True; ghosts are skipped), the grabber (required), and [vortac_qgl_state] (optional), then registers a T<tool_index> command for every available tool — the command comes from the INDEX, tool ids are names like miniGrey. TOOL= parameters accept the tool name (case-insensitive), T<n>, or a bare index. VORTAC_STATUS lists tools as <name> (T<index>).

Identity validation

Startup fails with a clear message if two tools share a tool_index, mcu_name, canbus_uuid, or sense pin, if the non-ghost tools' indices are not contiguous 0..N-1 (Klipper's extruder-naming contract; holds by construction with order-based numbering), if an available tool lacks tool_index, or if a tool's mcu_name has no matching [mcu …] section. Klipper itself merges duplicate config sections silently (last value wins), so a copied-but-not-fully-renamed tool file never errors on its own — this guard catches the detectable leftovers.

Probe guard

At klippy:connect the manager wraps the [probe] object's entry points (start_probe_session / run_probe), so every probe-based operation — QUAD_GANTRY_LEVEL, BED_MESH_CALIBRATE, PROBE, PROBE_ACCURACY, PROBE_CALIBRATE, … — refuses while a tool is held (logical current_tool OR any tool's grab_sense reading grabbed). Reason: the probe touch point sits above the nozzle tip when a tool is grabbed, so the nozzle would hit the bed before the probe triggers. Park the tool (VORTAC_UNLOAD) before probing.

Checked hook / unhook (sense-verified Z phases)

Both Z phases at the dock are stepwise and sense-verified with the same DOCK_UNHOOK_ZSTEP/DOCK_UNHOOK_LIFT_F constants; only the Y slides use DOCK_SLIDE_F. Every step waits for motion, lets the sense callbacks settle, and logs a checkpoint to klippy.log (vortac unhook …).

  • Fetch (unhook): engage, then checked lift — dock_sense must STAY LOW (going HIGH mid-lift = tilt/bind → lower back, re-seat, retry) — then checked Y backout where dock_sense going HIGH is the clean release. grab_sense HIGH at any checkpoint freezes motion (tool lost). Between the two phases the dock supply is cut in handover mode: the lift has just confirmed both a held tool and intact dock contact, which are exactly the two conditions that make handing the feed to the grabber safe (Dock power).
  • Park (hook-in): slide in lifted — this is where the pogos mate, so dock_sense is checked here with the dock still dead and the supply is switched on before anything moves again — then the checked drop from Z + DOCK_Z_CLEARANCE to the hooked Z, where dock_sense must be LOW before the grabber disengages; no contact → lift back up and retry (DOCK_UNHOOK_RETRIES), final failure de-energizes the dock and backs out with the tool still held. After disengage + backout, the tool must still read docked and no longer grabbed. Tools without sense pins hook in blind (slow drop, no verification, supply switched on unverified).

Dock detection (strobe-by-subtraction)

Every tool has two GPIO sense pins: dock_sense_pin (dock Tool_id after opto logic) and grab_sense_pin (default HIGH; pulled LOW by the grabber on the held tool).

Each dock's ARGB LED channels have fixed roles: green actively pulls the dock_sense pad low, red gates the parked tool board's supply (Dock power), and blue is a status LED whose content is selected by argb_status_mode. dock_sense readings are only valid while the dock's green channel is on; outside of the detection strobe, all docks keep the sense pull on. Every sense-dependent operation (tool change, VORTAC_LOAD/VORTAC_UNLOAD, calibration selection) first reconciles all three channels on every dock (_ensure_sense_active → _apply_dock_leds), so a manual SET_LED in between can neither silently disable the sense logic nor strand a tool board; the same state is asserted at klippy:ready.

VORTAC_DETECT:

  1. Energizes every dock for the whole pass and drops any transient supply override — a dead dock cannot report the tool sitting in it, so without this the detection would only ever confirm the map it started from.
  2. Turns the sense pull off on all docks.
  3. Strobes one dock's sense pull on at a time (dock_strobe_time, default 0.10 s). The status LED mirrors the strobe during a detection pass regardless of argb_status_mode, so you can watch it walk down the docks.
  4. Assigns the dock to any tool whose cached dock_sense_pin reads LOW.
  5. Restores the normal operating state afterwards: sense pull on everywhere, supply back under the occupancy policy, status LED per mode.

Docks the pass could not resolve — ambiguous ones, and all docks when some tool went unaccounted for — are recorded as uncertain and never de-energized. An unaccounted-for tool makes every dock suspect precisely because that tool may be sitting in a dock that read empty because its board was already dark. More than one tool reading grabbed at once has the same effect: physically impossible, so at least one grab_sense is lying, and a lying grab can hide a parked tool from the Missing list.

The grabbed tool is detected from grab_sense_pin. Detection aborts if any tool already reads dock LOW while all dock Tool_id channels are off (that would make the mapping ambiguous — see Troubleshooting).

Docks are established at runtime by this detection — home_dock is only an optional manual fallback. A grabbed tool is assigned the first free dock that has calibrated positions for it (a previous choice — fetch origin or manual home_dock — is kept if it is still free and calibrated); if no free calibrated dock exists, a warning is printed: VORTAC_UNLOAD/tool change will fail until a dock is calibrated for it or a dock is freed. The manager also remembers the dock a tool was fetched from and parks it back there — the park-dock resolution chain is detection map → fetch origin → optional home_dock. A tool change before any VORTAC_DETECT, for a tool without home_dock, fails with "no dock known … — run VORTAC_DETECT (or set home_dock on the tool)" — run detection before the first tool change (e.g. in PRINT_START).

Dock power (dark power management)

The parked tool board is fed through the dock's pogo pins, gated by the dock LED's red channel. The channel is inverted: red HIGH cuts the supply, red 0.0 means powered.

That polarity is mandatory, not a preference. Klipper sends klippy:mcu_identify — where every tool board must answer on the CAN bus — strictly before klippy:connect, which is when neopixel.py first transmits any colour. Nothing in Klipper can energize a dock before the tool boards are needed. If red HIGH meant “powered”, a cold boot would leave every dock dark and Klipper could never start. Keep initial_RED: 0.0 in the [neopixel] section.

Because dock_sense_pin and grab_sense_pin live on the tool's own MCU and Klipper has no notion of an optional MCU, a tool board that goes dark drops off the bus and takes klippy down. Everything below follows from that single constraint.

Where the contact is made and broken

The pogo contact opens and closes on the Y slide at the dock, never on Z: the spring-loaded dock board rides along through the whole Z travel (that is exactly why dock_sense is expected to stay LOW during the checked lift). So every supply switch brackets a Y move, and the contacts never make or break under load:

park  : approach lifted -> slide in Y   (contact closes, dock DEAD)
        -> verify dock_sense -> power ON
        -> checked Z drop -> disengage -> slide out Y

fetch : approach -> slide in Y -> engage
        -> checked Z lift -> verify grab_sense
        -> power OFF -> checked Y backout  (contact opens, dock DEAD)

In both directions the board is fed from the other side while the dock side switches: the grabber carries it during the fetch, the dock carries it after the park. There is never a moment where both feeds are down. The grabber-side contact is always made and broken live — it has no switch, and cannot get one.

Fail-safe rules

  • Only a dock positively known to be empty is de-energized. No detection yet, an ambiguous dock, a tool the pass could not place — anything uncertain stays live (_policy_power). “Could not place” is deliberately stricter than the Missing line VORTAC_DETECT prints: a tool that delivers no sense readings at all (sense pins absent but available: True) and an unavailable tool whose [mcu …] is still included can never be located, so they pin every dock on for the whole session.
  • Every failure exit of a fetch re-energizes the dock. Lost grab, stuck hooks, a failed re-seat: the tool may still be in that dock. On the retries-exhausted path the supply is restored before the grabber disengages, because from that moment the dock is the board's only feed.
  • RESTART and FIRMWARE_RESTART are wrapped to energize every dock first (_install_restart_guard). WS2812 latch their last value across a klippy restart, so a dock left dead would still be dead at the next mcu_identify. A full power cycle clears the latch and is the unconditional recovery path.
  • The supply is left alone at klippy:ready — every board is alive by then, and nothing may be switched off before the auto-detect has established which dock is empty.

Self-diagnosis: does the sense pull survive the cut?

The release criterion during the fetch backout is dock_sense going HIGH. If the dock's sense pull happened to be fed from the switched supply, cutting the supply would drive dock_sense HIGH immediately — with the tool not having moved at all — and every release check would silently pass. That is a false positive, worse than a failure.

So _power_off_before_backout probes for exactly that: right after the cut, with the tool still seated, dock_sense must still read LOW. If it does not, the supply is restored, sense_needs_dock_power is latched for the session, the dead-break half of the handover is disabled, and a message says so. _power_on_at_contact makes the mirror-image observation on the park side (no contact while dead, contact once live). VORTAC_STATUS and VORTAC_DOCK_POWER report the flag.

Other things this buys you

  • Dead pads at an empty dock. Exposed 24 V pads sit exactly where filament scraps and swarf land.
  • Unambiguous CAN UUID mapping. WS2812 latch, so VORTAC_DOCK_POWER DOCK=dockN VALUE=1 ONLY=1 FORCE=1, then systemctl stop klipper, then canbus_query.py — only the one powered board answers, which makes flash_can.py safe to aim.
  • Bus fault isolation while debugging a board that takes the whole bus down.

Not possible, for the record: staggering the power-up to soften PSU inrush (the LED is programmed after the boards are needed — hardware-only problem); switching docks off automatically on M112 or a shutdown (a shut-down MCU accepts no SET_LED); and saving power by de-energizing parked tools during a print (it costs an MCU, and it would break pre-heating the next tool while it is parked).

Dock calibration context

VORTAC_SELECT_DOCK DOCK=dockN runs detection and stores the detected dock/tool pair. VORTAC_DOCK_CAL_SAVE saves the current hooked/engage XYZ to that selected tool/dock and fails if no tool was detected. VORTAC_DOCK_SAVE_POS additionally refuses unless the gantry state is flat.

vortac_qgl_state — [vortac_qgl_state]

Toggles the gantry between frame-flat (dock geometry valid) and bed-flat (printing geometry valid) without re-probing.

  • Mechanic: at klippy:ready, hooks quad_gantry_level.z_helper.adjust_steppers to capture each delta vector into stored_deltas. FLAT replays −stored_deltas, TILT replays +stored_deltas. Wraps QUAD_GANTRY_LEVEL to zero stored_deltas when re-running while flat, so the new measurement starts clean.
  • Reset: homing:home_rails_end on any stepper_z* clears state and sets it to flat.
  • State is RAM only — power cycle, mid-print loss, or a fresh Z-home invalidates it; the user must re-run QGL.
  • Manager dependency: VORTAC_DOCK_SAVE_POS refuses unless state == 'flat'.

include_with — [include_with <namespace> <filename>]

Loads one Klipper template under a remapped MCU namespace; auto-renames sections per tool_index so one PCB-level config can be instantiated N times. The user-facing behavior (rename table, overrides, skip lists, pretty names) is documented in Configuration. Implementation notes:

  • tool_index is assigned by LOAD ORDER for tool templates: when the template carries a (non-skipped) [vortac_tool …] section, each [include_with] takes the next value from a per-printer counter — the first tool include in tools.cfg is 0, the next 1, … Commenting a tool out renumbers the ones after it, which keeps Klipper's extruder/extruder<N> contract intact. An explicit tool_index: wins; templates without a vortac_tool section fall back to the namespace's trailing number (tool1 → 1, else the option is required). Mixing explicit indices with auto-numbered includes is unsupported (the counter ignores explicit values).
  • Display-prefix renaming: every named section gets the DISPLAY prefix <namespace><tool_index> ([neopixel logo_rgb] → [neopixel miniGrey1_logo_rgb]; miniPink + index 0 → miniPink0_logo_rgb) — the index makes extruder1 ↔ miniGrey1_* visually matchable in Mainsail/Fluidd. Legacy digit-suffixed namespaces (tool1) stay as-is. Exceptions: [mcu] and [vortac_tool] keep the pure namespace. The display prefix shifts with order-based renumbering — safe, because the renamed hardware sections never hold SAVE_CONFIG data; address them index-proof in macros via {tool.display_name}_…. Full rename table in Configuration.
  • [vortac_tool TN] injection: the template's vortac_tool placeholder is renamed to [vortac_tool <namespace>] (PURE name, no index — this is the persistence anchor for SAVE_CONFIG'd dock positions), and tool_index, mcu_name (= namespace), display_name (<namespace><index>), canbus_uuid (from the static [mcu <namespace>] section) and extruder_name (the renamed extruder) are auto-injected. Template values and overrides win over the injection. home_dock is optional (docks come from VORTAC_DETECT at runtime); it can be pinned via overrides: (vortac_tool TN.home_dock: dockX). If SAVE_CONFIG's autosave block already created the section (persisted params_* dock positions), the injection MERGES into it — calibration data is preserved.
  • Value rewrite: any <from>: pin token in option values becomes <to>:; whole-string section refs (heater: extruder → heater: extruder1) are fixed up.
  • Built-in skip list for tool_index ≥ 1: resonance_tester, input_shaper, shaketune (Klipper singletons that can't be renamed). Config sections can also pass skip_sections: as a comma/newline list.
  • Overrides: the config option takes section.key: value lines; a JSON dict ({"section": {"key": "value"}}, null deletes) is also accepted and is the format of the programmatic overrides= argument.
  • Programmatic API (used by vortac_tool): include_with_remap(printer, parent_config, filepath, namespace, mcu_from=None, tool_index=0, overrides=None, skip_sections=None, template=None).

Lifecycle & dependencies

config parse:
  [vortac_grabber]    → register grabber gcode commands
  [vortac_qgl_state]  → register FLAT/TILT (hooks attach at klippy:ready)
  [mcu <name>]        → register tool MCU pin chip early
  [include_with ...]  → take next order-based tool_index, inject remapped
                        toolboard sections (incl. [vortac_tool <name>])
  [vortac_manager]    → register VORTAC_LOAD/UNLOAD/STATUS/DOCK_SAVE_POS;
                        defer rest to klippy:connect

klippy:ready    → vortac_qgl_state hooks QGL.adjust_steppers + QUAD_GANTRY_LEVEL
klippy:connect  → vortac_manager finds tools/grabber/qgl, validates identities,
                  registers T<index> commands

Hard dependencies:

  • vortac_manager requires [vortac_grabber].
  • Each active tool requires a static [mcu <name>] section before [include_with].
  • vortac_qgl_state requires [quad_gantry_level] to be defined.
