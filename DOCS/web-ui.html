Web UI

The Vortac dock panel as a browser page — served from the Pi, talking directly to Moonraker, and embeddable into the Mainsail dashboard as an iframe card.

How it works

Mainsail has no plugin system — its panels are compiled in. But Mainsail's webcam system has an official iframe service type that renders any URL as a dashboard card. So the Vortac UI is a normal web page that lives next to Mainsail:

  • web/index.html — one self-contained page (no build step, no dependencies). It speaks JSON-RPC over Moonraker's websocket and subscribes to the same status objects as the KlipperScreen panel: vortac_manager, vortac_tool <name>, vortac_qgl_state. Live updates, no polling.
  • nginx serves that folder on its own port (default 7130) — install.sh sets this up as a separate server block, so the Mainsail site config is never touched. Override the port with VORTAC_UI_PORT=… sudo ./install.sh.
  • Mainsail embeds the URL as an "iframe webcam" card, placeable on the dashboard like any panel.

Same data, same actions, same look as the KlipperScreen panel — dock tiles (tap to load/change/park/select), contextual Park/Load button, Detect, the contextual gantry toggle (Tilt/Flatten — the full coordinate-system switch, see vortac_qgl_state; disabled while a print runs), Engage/Disengage, Save Dock, all with confirm dialogs. Multiple browsers can be open at once, independent of the touchscreen.

Dock supply is mirrored here too (see Dock power): a bolt next to each dock name, lit while the dock feeds its tool board, and a Power: n/m chip in the header. A dock that holds a tool while its supply is off turns red and reads NO POWER — tap it to switch the supply back on. Switching a dock off is never offered from a UI: it costs an MCU and thus a klippy shutdown.

Setup — step by step

Web-UI checklist

Step 3 in detail: Moonraker CORS

The page is served from port 7130 but talks to Moonraker on port 7125 — a different origin, so Moonraker must allow it. In moonraker.conf, extend the [authorization] section:

[authorization]
cors_domains:
    *://my.mainsail.xyz
    *://*.local
    *://*:7130        # ← add this line (the Vortac web UI)
trusted_clients:
    …unchanged…

Then restart Moonraker: sudo systemctl restart moonraker. Keep whatever entries are already there — only the *://*:7130 line is new (match the port to VORTAC_UI_PORT if you changed it).

Step 4 in detail: the Mainsail card

Requires a current Mainsail

Older Mainsail releases don't have the HTML Iframe service yet — their service list still shows IP Camera in that spot. If HTML Iframe is missing from the dropdown, update Mainsail via the Update Manager and reload the browser (clear cache).

  1. Mainsail → Settings (gear) → Webcams → Add webcam.
  2. Name: Vortac. Service: HTML Iframe (leave the snapshot URL empty — it is not used by this type). URL: http://<pi>:7130/ (use the same hostname/IP you use for Mainsail — the page auto-connects to Moonraker on that same host).
  3. Save. The card appears wherever webcams show; arrange it on the dashboard via Mainsail's dashboard layout settings like any other panel.
Standalone use

The page is a full UI on its own — bookmark http://<pi>:7130/ on a phone or tablet. If Moonraker runs on a non-default host/port, pass it explicitly: http://<pi>:7130/?moonraker=host:port.

Troubleshooting

The card/page loads but says "disconnected — retrying"

Almost always CORS: Moonraker rejects the websocket because the origin (http://<pi>:7130) is not in cors_domains. Fix step 3 and restart Moonraker. Check the browser console (F12) — a blocked origin is reported there. Second candidate: the machine is reachable but Klipper is down — then the chip shows "klipper: shutdown/error" instead.

http://<pi>:7130/ is not reachable at all
  • nginx site missing — re-run sudo ./install.sh (it prints the URL on success; "nginx not found" means nginx isn't installed).
  • Config test failed — sudo nginx -t shows why; sudo systemctl reload nginx after fixing.
  • Port collision — some other service owns 7130: re-install with VORTAC_UI_PORT=7131 sudo ./install.sh and adjust the CORS entry and the iframe URL.
Mainsail is served via HTTPS and the card stays empty

Browsers block plain-HTTP iframes inside an HTTPS page (mixed content). Either serve Mainsail via HTTP on the LAN, or put the Vortac UI behind the same HTTPS proxy and use an https:// iframe URL — the page automatically switches to wss:// for the websocket when loaded over HTTPS.

Tiles/status look wrong

The page renders exactly the manager's status objects — if it disagrees with reality, the KlipperScreen panel and VORTAC_STATUS will disagree in the same way. Debug on that level (detection issues), not in the browser.

Kept in sync

The web UI and the KlipperScreen panel share the firmware's status contract (get_status fields). When one grows a feature, the other should follow — both are thin views over the same data.
