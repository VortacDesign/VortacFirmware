Print Calibration

Everything between a calibrated toolchanger and a machine that can actually print: gantry levelling, the Z reference, per-tool offsets, the bed mesh, and the per-tool extruder work.

Prerequisite

The toolchanger side must be done first — grabber LUT, zero position and every dock position from the Calibration chapter. Everything on this page assumes tool changes already work reliably, because several steps need a tool picked up and put back.

The order matters

These calibrations depend on each other, so run them in this sequence. Anything probe-based requires no tool held — the manager enforces that (see probe guard).

Print-calibration checklist

1 — Homing and the two gantry states

All four Z drivers run sensorless (StallGuard diag_pin + driver_SGTHRS on stepper_z…stepper_z3), homing upwards into the frame. That is what makes the flat state meaningful: after a Z home the gantry is parallel to the frame, which is the geometry the dock positions were calibrated in.

  • G28 → gantry flat, stored QGL deltas cleared ([vortac_qgl_state] resets on homing:home_rails_end of any stepper_z*).
  • QUAD_GANTRY_LEVEL → gantry tilted (parallel to the bed) — this is print geometry.
  • Check any time with VORTAC_QGL_STATUS.
The state lives in RAM only

A power cycle, a Klipper restart (SAVE_CONFIG restarts!), or a fresh Z home invalidates the tilt: the deltas are gone and the state is flat again. After every one of those, QGL must be re-run before printing.

2 — Quad gantry level

Run it with no tool held:

VORTAC_UNLOAD          # if a tool is still on the carriage
G28
QUAD_GANTRY_LEVEL
VORTAC_QGL_STATUS      # should now report tilted, with four stored deltas

The tracked configuration in mcu/octopus.cfg:

OptionValueWhat to check
gantry_corners-60,-40.8 / 360,329.4Must match where the Z belts actually pull on your frame — wrong corners make QGL converge slowly or not at all.
points30,0 · 30,220 · 270,220 · 270,0Nozzle coordinates. The probe sits y_offset: 33.8 behind the nozzle, so every point must stay reachable once that offset is added.
retry_tolerance0.02Tight but realistic for this gantry. If it never gets there, look at mechanics, not at the number.
retries5Should typically converge in 2–3.
max_adjust10Safety limit. Hitting it means the gantry is badly out or a Z motor is mis-wired.
horizontal_move_z5Travel height between probe points.
Good to know: how the FLAT/TILT trick works

[vortac_qgl_state] hooks the QGL helper and records the per-stepper delta vectors it applies. VORTAC_GANTRY_FLAT replays the negated deltas (back to frame-parallel, dock geometry valid), VORTAC_GANTRY_TILT replays them again (back to bed-parallel). No re-probing is needed, which is exactly what makes a mid-print tool change affordable. Re-running QUAD_GANTRY_LEVEL while flat zeroes the stored deltas first, so the new measurement starts clean.

Troubleshooting: QGL oscillates or refuses to converge
  • It refuses to start at all — a tool is held (probe guard). Park it.
  • Oscillating corrections — usually wrong gantry_corners, or a Z motor turning the wrong way.
  • Never reaches tolerance — check for binding, loose belts, and that the bed itself is not moving. Probe repeatability comes first: PROBE_ACCURACY (no tool!) should be well below retry_tolerance.
  • Fine right after homing, off later — something reset the state; check VORTAC_QGL_STATUS.

3 — The Z reference (probe z_offset)

The probe is mounted on the carriage, not on the tool ([probe] in mcu/vortac.cfg: pin: vortac:PA6, x_offset: 0, y_offset: 33.8). That has two consequences:

  • Probing works with the carriage empty — which is why the manager insists on it.
  • The probe measures the bed relative to the carriage. Turning that into "Z0 = bed surface for the nozzle" is what z_offset plus the per-tool gcode_offset_z do.
PROBE_CALIBRATE is not usable here

Klipper's PROBE_CALIBRATE wants you to paper-test the nozzle right after probing — but the nozzle belongs to a tool, and probing with a tool held is refused (and would crash the nozzle). Use the two-measurement procedure below instead.

Two-measurement procedure

Pick one tool as the reference tool (the one whose gcode_offset_z stays 0 — usually T0). Then, on a levelled gantry:

  1. With no tool, probe the bed centre and note the trigger Z — PROBE reports it (Result is z=…). Call it Z_probe.
  2. Pick up the reference tool (VORTAC_LOAD TOOL=<name>) and jog the nozzle down at the same XY until a sheet of paper just drags. Note that Z as Z_nozzle.
  3. The probe offset is the difference: z_offset = Z_probe − Z_nozzle. Enter it under [probe].

Verify by re-homing, running QGL, then commanding the nozzle to Z0 with the reference tool: the paper drag should be the same. Fine-tune live with SET_GCODE_OFFSET Z_ADJUST=… during a first layer and fold the result into z_offset afterwards.

Sign convention

Klipper adds the G-code offset to the commanded position, exactly like Z babystepping: a more positive Z offset raises the nozzle (thicker first layer), a more negative one lowers it.

4 — Per-tool offsets

Each tool carries three numbers on its [vortac_tool] section; the manager applies them with SET_GCODE_OFFSET … MOVE=0 on every tool change:

OptionDefaultMeaning
gcode_offset_x0.0nozzle X deviation from the reference tool
gcode_offset_y0.0nozzle Y deviation
gcode_offset_z0.0nozzle height deviation (positive = nozzle higher)
Where to write them

The [vortac_tool] section is injected from the PCB template, so you do not edit it directly — put the offsets into that tool's include_with overrides: block, using the template's original section name:

[include_with miniGrey vortac_configs/mcu/EBB42_V12.cfg]
skip_sections:
  mcu EBBCan
overrides:
  vortac_tool TN.gcode_offset_x: -0.30
  vortac_tool TN.gcode_offset_y:  0.15
  vortac_tool TN.gcode_offset_z: -0.05

Z offsets between tools

Reference tool stays at 0. For every other tool: load it, paper-test the nozzle at the same XY as in step 3, and enter the difference to the reference tool's touch height. A tool that touches later (nozzle sits higher) needs a negative gcode_offset_z.

The practical refinement: print a small single-layer patch with each tool, adjust live with SET_GCODE_OFFSET Z_ADJUST=… until the first layer matches the reference tool's, and copy the accumulated value into the config.

XY offsets between tools

Print a two-tool alignment pattern — e.g. a cross or a set of parallel lines drawn by the reference tool, with the same pattern drawn on top by the second tool. Measure the shift, then subtract it: if T1's lines land 0.3 mm too far in +X, set gcode_offset_x: -0.30. Repeat until the two patterns coincide; 0.05 mm is a realistic target.

Check repeatability first

Offsets are only meaningful if the pickup is repeatable. Run VORTAC_UNLOAD/VORTAC_LOAD for the same tool several times and re-print the pattern. If it moves between pickups, fix the mechanics (dock position, grabber engage angle, kinematic coupling) before chasing offset numbers.

5 — Bed mesh

Again: no tool held, gantry levelled.

VORTAC_UNLOAD
G28
QUAD_GANTRY_LEVEL
BED_MESH_CALIBRATE PROFILE=default
SAVE_CONFIG

The tracked configuration in mcu/octopus.cfg:

OptionValueWhat to check
mesh_min10, 40Probe coordinates. Y must stay ≥ the probe's y_offset (33.8) so the nozzle stays on the bed while the probe reaches the front row.
mesh_max290, 250Rear limit is bounded by y_offset too: the carriage travels 33.8 mm further back than the probed point.
probe_count3, 3Fine for a quick check; raise it (5×5, 7×7) for the profile you actually print with.
horizontal_move_z4Must clear any clips/warping.
fade_start / fade_end / fade_target1 / 10 / 0Mesh compensation fades out between Z1 and Z10 mm.
speed200Travel speed between points.

The mesh describes the bed surface relative to the levelled gantry, so it is only valid together with a QGL run — and it is tool-independent (the probe is on the carriage). Per-tool height differences are handled by gcode_offset_z, not by the mesh.

Mesh at printing temperature

Calibrate with the bed at its actual print temperature and after a proper heat soak — a cold mesh on a heated bed is worse than no mesh. If you print at several bed temperatures, save one profile per temperature (PROFILE=pei_100) and load it in your print-start macro.

6 — Per-tool extruder and heater calibration

Every tool is its own extruder and its own hotend, so these are per tool. Klipper names them index-based: the first tool owns extruder, the next extruder1, and so on (see include_with).

ACTIVATE_EXTRUDER EXTRUDER=extruder1     # select the tool's extruder
PID_CALIBRATE HEATER=extruder1 TARGET=240
SAVE_CONFIG
  • Hotend PID — once per tool, at a typical print temperature. The bed (HEATER=heater_bed) only once for the machine.
  • rotation_distance — the shared template ships one value (21.95 with gear_ratio: 50:10 on the SB2209 template). Extruders differ; measure per tool (mark 120 mm of filament, extrude 100 mm, compute) and put a deviating value into that tool's overrides: — extruder.rotation_distance: 22.10 — never into the shared template.
  • Pressure advance, flow, temperature towers — per tool as well, since hotend and nozzle differ. Pressure advance can live in the config (extruder.pressure_advance via overrides) or in the slicer's per-tool filament settings.
  • Thermistor / RTD type — also an override, not a template edit. See Configuration → overrides for the MAX31865 example and the reference-resistor trap.

7 — Resonance / input shaper per tool

Every tool board carries its own ADXL345, and include_with namespaces it ([adxl345] → [adxl345 miniGrey]). But [resonance_tester], [input_shaper] and [shaketune] are Klipper singletons — they cannot exist once per tool, which is why the tool configs skip them via skip_sections:.

The consequence for calibration:

  1. Declare [resonance_tester] once (in printer.cfg), pointing at the tool you are currently measuring — the accel chip name is the namespaced one: 
    [resonance_tester]
accel_chip: adxl345 miniGrey
probe_points: 150, 150, 20
  2. Pick that tool up, run SHAPER_CALIBRATE (or Shake&Tune), and note the resulting shaper type and frequencies. Repeat per tool, re-pointing accel_chip each time.
  3. Since only one [input_shaper] section can exist, apply the per-tool values at tool-change time instead of storing them statically — in that tool's tool_activate_gcode: 
    overrides:
  vortac_tool TN.tool_activate_gcode: SET_INPUT_SHAPER SHAPER_TYPE_X=mzv SHAPER_FREQ_X=57.8 SHAPER_TYPE_Y=mzv SHAPER_FREQ_Y=46.0

    Overrides are parsed one entry per line, so a value spanning several G-code lines does not work in this format. For a multi-command hook use the JSON form of overrides:, where \n separates the commands:

    overrides: {"vortac_tool TN": {"tool_activate_gcode":
  "ACTIVATE_EXTRUDER EXTRUDER=extruder1\nSET_INPUT_SHAPER SHAPER_FREQ_X=57.8 SHAPER_FREQ_Y=46.0"}}
Measure with the tool actually held

The moving mass includes the tool, so resonances differ per tool — that is the whole reason for doing this per tool. Load the tool before measuring, and keep the gantry in its normal printing (tilted) state.
