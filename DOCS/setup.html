Installation & Setup

Bringing up a Vortac toolchanger from scratch — from flashing a toolhead board to a running installation. Checkboxes are saved in your browser, so you can work through the list across sessions.

Bring-up checklist

1 — Flash the toolhead board

Flash Katapult (bootloader) and Klipper onto the CAN toolhead board. Follow the excellent guide at canbus.esoterical.online.

After flashing, query the board's CAN bus UUID — you will need it for the tool config:

~/klippy-env/bin/python ~/klipper/scripts/canbus_query.py can0
Good to know: every board has a unique UUID

The UUID is burned into the MCU, not assigned by you. When you add a second tool with the same PCB, only the tool name (the [mcu <name>] / include_with namespace) and the UUID differ between the two tool config files — the entire rest of the hardware definition comes from one shared template (see include_with).

2 — Install VortacFirmware on the Pi

Clone the repository directly:

git clone https://github.com/VortacDesign/VortacFirmware.git ~/vortac

…or let Moonraker manage updates by adding this to moonraker.conf (adjust path/branch if needed):

[update_manager vortac]
type: git_repo
path: ~/vortac
origin: https://github.com/VortacDesign/VortacFirmware.git
primary_branch: development
managed_services: klipper

Then run the installer once, as root:

cd ~/vortac && sudo ./install.sh

What the installer actually does

  1. Symlinks every *.py from the repo's klippy/extras/ into Klipper's klippy/extras/ (top-level only; existing non-symlink files are skipped, never overwritten).
  2. Sets up a systemd bind-mount + automount that exposes configs/vortac_configs/ at ~/printer_data/config/vortac_configs/.
  3. Installs a systemd .path watcher on .git/refs/heads/<branch> and .git/packed-refs — every git pull re-runs install.sh automatically.

So the installer is normally a one-time step. After any update: sudo systemctl restart klipper.

uninstall.sh reverses everything (removes the systemd units, unmounts, deletes the symlinks).

vortac_configs/ shows up empty?

Run install.sh manually once more, then clear your browser cache and reload the web interface — Mainsail/Fluidd caches the file tree. See Troubleshooting.

3 — Wire up printer.cfg

Include the Vortac configs from your printer.cfg in this order (boot order matters — each tool file must declare its [mcu <name>] before the template include runs):

[include vortac_configs/mcu/octopus.cfg]   # mainboard: XY, Z×4, bed, dock LEDs, [printer]
[include vortac_configs/mcu/vortac.cfg]    # grabber MCU + [vortac_grabber] + [vortac_qgl_state]
[include vortac_configs/tools.cfg]         # per-tool includes + [vortac_manager]

A ready-made template is in the repo: configs/printer.example.cfg. Pick the mainboard include that matches your hardware from vortac_configs/mcu/ (currently octopus.cfg; kraken.cfg is a placeholder) and verify stepper/fan/LED pins against your wiring.

Good to know: the .example pattern

The repo only ships *.example.cfg templates for user-specific files. The real files (printer.cfg, tools.cfg, every tools/*.cfg) are gitignored — they contain your CAN UUIDs, dock positions and offsets. Copy <name>.example.cfg → <name>.cfg and edit. Klipper never reads .example files; it only loads what printer.cfg pulls in via [include]. General hardware configs (everything under mcu/) stay tracked as-is.

4 — Set up tools.cfg and the tool files

vortac_configs/tools.cfg is the tool registry: it includes one file per tool and configures [vortac_manager]. Start from the templates:

cd ~/printer_data/config/vortac_configs
cp tools.example.cfg tools.cfg
cp tools/tool0.example.cfg tools/myTool.cfg   # any name — it is NOT the tool number

In the tool file, set the board's canbus_uuid (from step 1). The tool's number is its include position in tools.cfg (first include = T0); its name is the [mcu <name>] / include_with namespace. The tool's dock is established at runtime by VORTAC_DETECT, and dock positions are calibrated at runtime and persisted via SAVE_CONFIG — nothing to write by hand. The full walk-through for the file contents — and for adding more tools — is in Configuration → Adding a tool.

Restart Klipper after config changes:

sudo systemctl restart klipper
The manager checks your work

On startup, vortac_manager refuses to start — with a clear message — if two tools share a tool_index, mcu_name, canbus_uuid or sense pin, if the tool indices are not contiguous 0..N-1, or if a tool's mcu_name has no matching [mcu …] section. Fix exactly what it names.

5 — First tests

After calibration, verify the setup layer by layer:

Grabber only (no tool attached)

VORTAC_SIMPLE_READ        ; sensor sanity check — raw and true angle
VORTAC_ENGAGE             ; move to engage_pos (default 130)
VORTAC_DISENGAGE          ; move to disengage_pos (default 0)

Both are closed-loop moves and should converge within tolerance (default ±2°) in 1–2 moves — the console reports e.g. Reached 130.02° … in 1 move(s).

Sense pins and dock detection (tools parked in their docks)

VORTAC_SENSE_STATUS       ; raw dock/grab sense pin states per tool
VORTAC_DETECT             ; strobe-based dock occupancy + grabbed tool
VORTAC_STATUS             ; current tool, dock map, QGL state

VORTAC_DETECT also establishes the dock map tool changes rely on — run it before the first tool change (e.g. in PRINT_START).

First manual tool change (after dock positions are calibrated)

VORTAC_LOAD TOOL=T0       ; fetch T0 from its dock (TOOL= also takes the name: TOOL=miniGrey)
VORTAC_UNLOAD             ; park it back
T0                        ; full tool-change command
